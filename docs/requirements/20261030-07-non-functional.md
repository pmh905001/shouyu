# 07 非功能需求

> 状态：草稿 ｜ 更新：2026-10-30
>
> 下表里的数值都是整理时给出的建议目标，需要用户确认。

## 1. 数据规模预估

依据：本机现有数据，统计于 2026-10-30。

| 项 | 现状 | 按 5 年使用预估 |
|---|---|---|
| Cursor 会话 | `sand-api` 228 个，工作区 164 个，其他项目约 13 个 | 5000 个以上 |
| 单个 Cursor 会话 | 几十 KB 到几百 KB，大部分是 AI 读文件、跑命令的输出 | |
| 随手记、截图 | 每天若干条 | 数万条 |
| 任务、番茄 | 每天几条到十几条 | 数万条 |

## 2. 需求清单

| 编号 | 需求 | 优先级 | 来源 | 验收标准 |
|---|---|---|---|---|
| NFR-01 | 不打断：保存不切换窗口，不抢焦点，正常保存时不弹出需要点击的对话框 | P0 | 用户（v1 的设计理念） | 保存时前台窗口的焦点不变 |
| NFR-02 | 只用键盘也能完成采集、搜索、浏览 | P0 | 用户（v1 的设计理念） | 不碰鼠标就能完成这些操作 |
| NFR-03 | 保存快：从按下快捷键到出现提示 | P0 | 用户 | 建议在 300 毫秒以内 |
| NFR-04 | Cursor 问答采集的延迟 | P0 | 建议 | 一轮问答结束后，建议在 1 分钟以内能搜到 |
| NFR-05 | 搜索快 | P0 | 建议 | 按 5 年的数据量，建议关键词搜索在 1 秒以内出结果 |
| NFR-06 | 界面不卡：任何后台工作都不能让界面失去响应 | P0 | 用户（v1 出现过卡死 262 秒的问题） | 后台大批量导入时，界面仍然能正常操作 |
| NFR-07 | 不丢数据：程序崩溃、断电、强制结束后，已提示保存的数据都在 | P0 | 用户 | 同 CAP-10 |
| NFR-08 | 全部数据只存在本机，不上传到任何云端 | P0 | 用户 | 断网后所有采集、存储、搜索功能都能正常使用 |
| NFR-09 | 调用外部服务（大模型、外部搜索）必须是用户主动发起或明确开启的，可以随时关闭，并且清楚标出会发出去哪些内容 | P0 | 建议 | 关掉外部服务后，程序不发出任何外部请求 |
| NFR-10 | 运行环境：Windows 10/11，可以打包成单个 exe 运行 | P0 | 用户（v1 已有） | 在没有装 Python 的电脑上能运行 |
| NFR-11 | v1 和 v2 可以安装在同一台电脑上，互不破坏对方的数据 | P0 | 用户 | 两者的数据库、日志、状态文件、备份互相独立 |
| NFR-12 | 磁盘占用可控：能看到各类数据占了多少空间，能清理不需要的大内容 | P1 | 建议 | 有地方能看到占用情况 |
| NFR-13 | 出问题时能排查：有错误日志和崩溃日志 | P0 | 用户（v1 已有） | 同 INH-30 |
