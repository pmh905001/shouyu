# 02 信息采集

> 状态：草稿 ｜ 更新：2026-10-30

## 1. 场景

| 场景 | 期望 |
|---|---|
| 看资料时选中一段文字或截了一张图 | 按一下快捷键就保存，弹出气泡提示，不切换窗口 |
| 屏幕上有文字但不能复制（图片、视频、远程桌面） | 框选一块区域，识别出其中的文字并保存 |
| 在 Cursor 里和 AI 来回讨论了半小时 | 不需要任何操作，整段问答自动保存，后面继续追问的内容也会持续保存 |
| 在 Qwen 或元宝网页上问了问题 | 能把这次问答保存下来，和 Cursor 的问答放在一起 |
| 完成了一个任务、写了反思、做完一个番茄 | 这些活动本身也成为记录，可以作为找回其他记录的时间线索 |
| 记下一条内容时 | 自动带上当时的上下文，以后回看能知道当时在做什么 |

## 2. 需求清单

| 编号 | 需求 | 优先级 | 来源 | 验收标准 |
|---|---|---|---|---|
| CAP-01 | 用快捷键保存剪贴板里的文字或图片 | P0 | 用户（v1 已有） | 按键后立即出现保存提示，不切换窗口；任何情况下都不需要等待 Excel 等其他程序 |
| CAP-02 | 框选屏幕区域，识别其中的文字并保存 | P1 | 用户（v1 已有） | 和 v1 的 `ctrl+alt+o` 行为一致 |
| CAP-03 | 采集时自动记录上下文：时间、前台程序、窗口标题；浏览器里还要记网址；如果有进行中的任务或番茄，也要记下来 | P0 | 用户 | 任意一条记录都能看到这些上下文；没有的项留空，不影响保存 |
| CAP-04 | 自动、持续地采集 Cursor 的问答：新会话、已有会话里的新消息都要保存，不需要手动操作 | P0 | 用户 | Cursor 里新的一轮问答结束后，在可接受的延迟内（见 NFR-04）能在 v2 里搜到 |
| CAP-05 | Cursor 问答要保存提问、回答、所属项目，以及 AI 在会话中读过、改过的文件 | P0 | 用户 | 打开任意一个保存的会话，能看到这些信息 |
| CAP-06 | 首次使用时，导入本机已有的全部 Cursor 历史会话 | P0 | 建议 | 本机已有的会话都能在 v2 里找到 |
| CAP-07 | 采集 Qwen 和元宝的问答 | P1 | 用户 | 至少能手动一键保存当前页面的完整会话；能自动采集更好（见 Q3） |
| CAP-08 | 任务、Backlog、番茄、习惯、反思等活动也作为记录保存 | P0 | 建议 | 能在时间线上看到"几点开始了哪个任务、几点完成、做了几个番茄" |
| CAP-09 | 同一内容重复采集时不产生重复记录；同一会话更新时，在原记录上追加内容，不另建一条 | P0 | 建议 | 同一个 Cursor 会话导入多次，结果仍然只有一个会话，消息也不重复 |
| CAP-10 | 采集不丢失：程序崩溃、重启、电脑休眠后，已经提示"已保存"的内容都还在 | P0 | 用户（v1 已有） | 保存后立刻强制结束进程，重启后记录仍然存在 |
| CAP-11 | 采集失败时让用户知道，并且能重试 | P1 | 建议 | 失败会提示，并且有地方能看到失败的条目 |
| CAP-12 | 能方便地增加新的采集来源，比如以后接入 ChatGPT、Claude、浏览器书签 | P2 | 建议 | 增加一个来源时，不需要修改已有来源的代码 |
| CAP-13 | 采集到的内容里如果有密码、密钥、连接串，可以自动打码或标记为敏感 | P1 | 建议 | 测试用的假密钥在保存后不以明文出现在搜索结果里（具体规则见 Q8） |
