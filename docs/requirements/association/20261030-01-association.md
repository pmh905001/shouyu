# 关联（信息网络）

> 状态：草稿 ｜ 更新：2026-10-31
>
> "现状"一列的含义见 [docs/README.md](../../README.md#实现状态标记)。依据是 v2 分支起点 `ba6c474` 的代码，也就是 v1 的代码。

## 1. 为什么需要关联

单条记录往往看不懂，因为缺少当时的上下文（见 [总览](../overview/20261030-01-overview.md) 痛点 5）。把记录按以下线索连起来，看到一条记录时就能顺着线索找到相关的其他记录：

| 线索 | 举例 |
|---|---|
| 时间 | 下午 3 点到 3 点半之间，所有来源产生的记录 |
| 任务 | 做"修复 SSE 断流"这个任务期间，在 Cursor 里的问答、截图、随手记 |
| 项目和代码 | 所有涉及 `sand-api` 仓库里 `internal/graph/node/xxx.go` 的问答 |
| 共同内容 | 都提到同一个报错信息、同一张表、同一个网址的记录 |
| 意思相近 | 用词不同，但讨论的是同一件事 |
| 手工 | 我自己认为这两条有关系 |

## 2. 场景

| 场景 | 期望 |
|---|---|
| 搜到一条随手记，但想不起为什么记 | 能看到它是在做哪个任务时记的，同一时段还问了 AI 什么 |
| 准备修改某个文件 | 能列出以前所有涉及这个文件的问答和记录，避免重复踩坑 |
| 在 Cursor 和 Qwen 上分别问过同一个问题 | 两次问答能互相关联 |
| 回顾某个任务 | 能看到这个任务从创建、推进到完成的全过程，以及过程中产生的所有记录 |
| 看到一条关联 | 能知道它为什么被关联，可以删掉错误的关联 |

## 3. 需求清单

| 编号 | 需求 | 优先级 | 来源 | 验收标准 | 现状 |
|---|---|---|---|---|---|
| ASC-01 | 时间关联：能查看任意一个时间点前后，跨所有来源的记录 | P0 | 用户 | 选中一条记录，能看到它前后 N 分钟内的其他记录（N 可以调整） | 部分实现：只能按天看，每天一个工作表；文字记录没有时间，做不到按分钟查看；只有 shouyu 自己的记录 |
| ASC-02 | 任务关联：任务进行期间或番茄进行期间产生的记录，自动归到这个任务下 | P0 | 建议 | 在番茄里做任务 A 时保存的随手记，打开任务 A 能看到它 | 部分实现：番茄记录会写在进行中任务的标题下（`excel.py` 的 `append_detail`）；随手记和截图写在"其他"区域，不归到任务下 |
| ASC-03 | 工作片段：没有开番茄时，也能把时间上连续的活动自动归为一段 | P1 | 建议 | 中间隔了较长空闲的两段活动，会被分成两个片段 | 未实现：已有空闲检测（`shouyu/util/idle.py`），但只用于番茄的走神提醒 |
| ASC-04 | 项目和代码关联：问答和记录关联到项目、仓库、分支或提交、涉及的文件 | P0 | 用户 | 能按项目筛选；能按文件路径查出所有相关会话 | 未实现 |
| ASC-05 | 共同内容关联：提到同一个文件、网址、报错、表名、接口名的记录，自动互相关联 | P1 | 建议 | 两个不同会话都提到同一个报错时，能从一个跳到另一个 | 未实现 |
| ASC-06 | 意思相近的关联：用词不同但内容相关的记录能被关联 | P1 | 用户 | 搜"接口超时"，能找到写着"请求卡住不返回"的记录 | 未实现：v1 README 里列为 TODO |
| ASC-07 | 手工关联：可以手动把两条记录连起来、打标签、标记"有用" | P1 | 建议 | 手动建立的关联和标签保存后不会丢失，不会被自动整理覆盖 | 未实现 |
| ASC-08 | 关联可以解释：每条关联都能看出是怎么来的（时间、任务、文件、意思相近、手工） | P1 | 建议 | 在界面上能看到关联的原因 | 未实现 |
| ASC-09 | 关联可以修正：错误的自动关联能删除，删除后不会被重新生成 | P2 | 建议 | 删除一条自动关联后重新整理，它不会再出现 | 未实现 |
| ASC-10 | 能从一条记录出发，沿关联一层层展开查看 | P1 | 用户 | 从一条记录出发，至少能展开两层关联 | 未实现 |
