# v2 设计文档

> 状态：未开始。每个里程碑的需求细化并定稿后，才开始写这个里程碑的设计（见 [路线图](../roadmap.md)）。

## 编写规则

- 每个设计决策都注明对应的需求编号，比如"满足 CAP-04、STO-07"。
- 设计过程中如果发现需求有遗漏或有矛盾，先修改需求文档，再继续设计。
- 每篇设计文档的结构：背景 → 目标 → 架构设计 → 具体改动 → 待确认项。
- 只设计当前里程碑要用到的部分，不提前设计后面的里程碑。为后面留的扩展点，写在"待确认项"里说明。

## 文件夹

和 `requirements/` 一一对应，只分一层：`overview/`、`capture/`、`storage/`、`association/`、`retrieval/`，以后按需增加，比如 `planning/`。文件命名规则见 [../README.md](../README.md#文件命名)。
